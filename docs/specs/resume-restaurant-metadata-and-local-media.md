# Restaurant Metadata and Local Media Specification

## Status

이 문서는 이력서 작성 도구에 레스토랑 메타정보와 브라우저 로컬 사진을 추가하는 승인된 설계를 정의합니다.
이 문서의 범위는 이력서 프로토타입에 구현했습니다.
현재 Track A의 검증 범위와 개인정보 보호 경계는 `docs/specs/initial-product-scope.md`를 따릅니다.

## Goal

동일한 이름의 레스토랑을 위치로 구분하고, 사용자가 근무 당시의 주요 이력과 작업 사진을 자신의 경력에 연결할 수 있게 합니다.
사진은 현재 기기에서 이력서를 작성하고 PDF를 출력하는 데 사용하며, 사용자가 별도로 공개하기 전에는 브라우저 밖으로 전송하지 않습니다.

## Product Decisions

- 레스토랑 위치와 주요 이력은 사용자가 작성한 정보로 취급합니다.
- 주요 이력은 미쉐린 가이드, The World's 50 Best Restaurants 등 근무 경력을 이해하는 데 필요한 사실을 자유 형식으로 최대 5개까지 입력받습니다.
- 프로필 사진은 전체 이력서에 최대 1개를 저장합니다.
- 음식이나 작업물 사진은 경력별로 최대 6개를 저장합니다.
- 작업 사진마다 `메뉴명 · 본인이 맡은 부분`을 설명하는 짧은 문구를 필수로 입력받습니다.
- 사용자는 각 경력에서 최대 1개를 PDF 대표사진으로 선택할 수 있습니다.
- PDF 대표사진은 기본적으로 선택하지 않습니다.
- 개인적으로 만들거나 개발한 메뉴를 이력서 전체에 연결하는 별도 사진 영역은 이번 범위에서 제외합니다.
- 향후 온라인 포트폴리오는 경력별 사진을 모두 보여줄 수 있지만, 공개 URL과 서버 저장은 이번 범위에서 제외합니다.

## Scope

### Restaurant Metadata

각 `CareerEntry`에는 다음 필드를 추가합니다.

```typescript
type CareerEntry = {
  restaurantLocation: string;
  restaurantHighlights: string[];
};
```

`restaurantLocation`은 지점이나 도시를 포함한 상세 위치를 사용자가 직접 입력하는 단일 문자열입니다.
예시는 `서울 용산구 한남동`과 `서울 강남구 청담동 도산대로점`입니다.
값은 선택 사항이며, 앞뒤 공백을 제거한 뒤 최대 100자로 제한합니다.

`restaurantHighlights`는 근무 당시 레스토랑을 설명하는 주요 이력입니다.
각 항목은 앞뒤 공백을 제거한 뒤 1자 이상 80자 이하이어야 하며, 최대 5개까지 저장합니다.
입력 화면은 `미쉐린 1스타 (2019–2021)`처럼 명칭과 적용 시기를 함께 적도록 안내합니다.
제품은 이 문자열을 외부 데이터와 대조하거나 검증된 사실로 표시하지 않습니다.

### Profile Photo

`ResumeIdentity`에는 다음 필드를 추가합니다.

```typescript
type ResumeIdentity = {
  profilePhotoId: string | null;
};
```

프로필 사진은 최대 1개입니다.
프로필 사진을 추가하면 일반 미리보기와 일반 PDF의 이력서 머리말에 표시합니다.
리뷰용 사본에서는 이름, 이메일, 전화번호와 함께 프로필 사진도 자동으로 제외합니다.
프로필 사진은 경력별 PDF 대표사진과 별개의 자산입니다.

### Career Portfolio Photos

각 `CareerEntry`에는 다음 필드를 추가합니다.

```typescript
export type CareerPhotoReference = {
  assetId: string;
  description: string;
};

type CareerEntry = {
  portfolioPhotos: CareerPhotoReference[];
  resumePhotoId: string | null;
};
```

`portfolioPhotos`는 업로드 순서를 유지하며 최대 6개까지 저장합니다.
`description`은 `메뉴명 · 본인이 맡은 부분`을 설명하는 사용자 작성 문자열이며, 앞뒤 공백을 제거한 뒤 1자 이상 120자 이하이어야 합니다.
설명이 없는 사진이 있으면 사용자는 미리보기 단계로 이동할 수 없습니다.

`resumePhotoId`는 같은 경력의 `portfolioPhotos[].assetId` 중 하나이거나 `null`이어야 합니다.
초기값은 `null`입니다.
대표사진을 삭제하면 `resumePhotoId`도 즉시 `null`로 변경합니다.
사진을 다른 경력으로 이동하는 기능과 사진 순서를 바꾸는 기능은 포함하지 않습니다.

## Local Photo Asset

구조화된 초안에는 사진 ID와 설명만 저장합니다.
실제 이미지 Blob은 별도 IndexedDB에 저장합니다.

```typescript
export type LocalPhotoAsset = {
  id: string;
  blob: Blob;
  mimeType: "image/jpeg";
  width: number;
  height: number;
  byteLength: number;
  createdAt: string;
};
```

데이터베이스 이름은 `mise-en-place-media`이고, 객체 저장소 이름은 `photos`입니다.
사진 원본은 저장하지 않습니다.
브라우저에서 디코딩한 이미지는 Canvas에 다시 그린 뒤 JPEG로 정규화하여 저장합니다.
이 과정은 원본 파일에 포함된 EXIF 메타정보를 로컬 자산에 복사하지 않기 위한 처리이기도 합니다.

파일 선택기는 JPEG, PNG, WebP, HEIC, HEIF를 선택할 수 있게 합니다.
실제 지원 여부는 현재 브라우저가 해당 파일을 디코딩할 수 있는지로 판정합니다.
애니메이션 GIF와 SVG는 받지 않습니다.
입력 파일은 20 MB 이하이어야 합니다.
저장 자산은 긴 변을 최대 1,600 px로 줄이고, JPEG 인코딩 품질을 단계적으로 낮추거나 크기를 추가로 축소하여 2 MB 이하로 만듭니다.
2 MB 이하로 만들 수 없으면 저장하지 않고 다시 선택하라는 오류를 표시합니다.

## Draft Schema and Migration

현재 구조화된 초안 버전 2를 버전 3으로 올립니다.
버전 1과 버전 2 초안은 다음 기본값을 사용하여 버전 3 모델로 읽습니다.

```typescript
const migratedDefaults = {
  profilePhotoId: null,
  restaurantLocation: "",
  restaurantHighlights: [],
  portfolioPhotos: [],
  resumePhotoId: null,
};
```

버전 3 파서는 다음 불변 조건을 검사합니다.

- 각 경력의 `portfolioPhotos`는 6개를 넘지 않습니다.
- 한 경력 안에서 `assetId`는 중복되지 않습니다.
- 각 설명은 문자열이며 120자를 넘지 않습니다.
- `resumePhotoId`는 같은 경력에 속한 사진 ID이거나 `null`입니다.
- 모든 사진 ID는 비어 있지 않은 문자열입니다.
- 기존 규칙과 마찬가지로 재직 중인 경력은 최대 1개입니다.

초안 JSON이 구조적으로 잘못되면 일부만 복원하지 않고 전체 복원을 거부합니다.
IndexedDB에 실제 Blob이 없는 사진 참조는 초안 JSON 오류와 구분합니다.
이 경우 나머지 구조화된 초안은 복원하고, 끊어진 사진 참조만 제거한 뒤 사용자에게 사진 일부를 복원하지 못했다고 알립니다.

## Storage Consistency

`localStorage`와 IndexedDB는 하나의 트랜잭션으로 묶을 수 없으므로 다음 순서를 사용합니다.

### Add Photo

1. 선택한 파일을 브라우저에서 디코딩하고 정규화합니다.
2. 새 자산을 IndexedDB에 저장합니다.
3. 해당 자산 ID를 현재 React 상태와 구조화된 초안에 연결합니다.
4. 구조화된 초안 저장에 실패하면 방금 만든 자산을 삭제합니다.

### Remove Photo

1. 구조화된 초안과 현재 React 상태에서 사진 참조를 먼저 제거합니다.
2. 삭제한 사진이 대표사진이면 대표사진 선택도 해제합니다.
3. IndexedDB에서 Blob을 삭제합니다.
4. Blob 삭제에 실패하면 다음 복원 시 고아 자산 정리가 다시 삭제를 시도합니다.

### Restore Draft

1. 애플리케이션을 열면 저장된 초안을 사용자 화면에 적용하지 않은 상태로 파싱하여 유효한 사진 참조만 수집합니다.
2. 저장된 유효한 초안이 없으면 IndexedDB의 사진을 모두 고아 자산으로 삭제합니다.
3. 사용자가 명시적으로 복원을 선택하면 구조화된 초안을 화면 상태에 적용합니다.
4. 초안이 참조하는 모든 사진 ID를 IndexedDB에서 조회합니다.
5. 존재하지 않는 사진 참조를 제거하고 경고를 표시합니다.
6. 초안이 참조하지 않는 IndexedDB 자산을 고아 자산으로 삭제합니다.

### Delete Draft

사용자가 초안 삭제를 확인하면 구조화된 초안과 `photos` 객체 저장소의 모든 자산을 함께 삭제합니다.
한쪽 삭제가 실패하면 완료로 표시하지 않고 다시 시도할 수 있는 오류를 보여줍니다.

## User Flow

### STEP 02: 경력 확인

레스토랑명 아래에 상세 위치와 주요 이력 입력을 배치합니다.
원문 사업장명과 건강보험 자격일은 기존과 같이 수정할 수 없는 원문 정보로 유지합니다.
상세 위치와 주요 이력은 `본인이 작성함`으로 표시합니다.

### STEP 03: 경력 보완

신원 정보 영역에는 프로필 사진 1개를 추가하거나 교체하고 삭제하는 조작을 제공합니다.
각 경력에는 최대 6개의 작업 사진을 추가하는 갤러리를 제공합니다.
사진 카드에는 미리보기, 필수 설명 입력, `PDF 대표사진` 단일 선택, 삭제 조작을 함께 배치합니다.
6개가 채워지면 추가 조작을 비활성화하고 한도를 설명합니다.

사진 디코딩, 정규화, 저장 중에는 해당 사진 카드에 진행 상태를 표시합니다.
오류가 발생해도 이미 작성한 텍스트와 다른 사진은 유지합니다.

### STEP 04: Preview and PDF

일반 미리보기와 일반 PDF에는 프로필 사진과 사용자가 선택한 경력별 대표사진을 표시합니다.
PDF에는 `resumePhotoId`가 지정된 경력마다 사진 1개만 표시합니다.
사진은 원본 비율을 유지한 채 정해진 영역 안에 맞추며, 얼굴이나 작업물을 임의로 잘라내지 않습니다.
선택한 자산을 읽거나 디코딩할 수 없으면 깨진 이미지로 출력하지 않고, 출력 전에 해당 경력의 사진을 다시 선택하라는 오류를 표시합니다.

리뷰용 사본은 프로필 사진을 제외합니다.
사용자가 경력 증거로 명시적으로 선택한 경력별 대표사진은 리뷰용 사본에 유지합니다.

## Privacy and Network Boundary

- 선택한 파일, 정규화한 Blob, Object URL, 사진 설명은 현재 브라우저 안에서만 처리합니다.
- 사진 업로드나 초안 저장은 네트워크 요청을 발생시키지 않습니다.
- 분석, 로그, 세션 기록, 오류 보고 도구에 파일명, Blob, Object URL, 사진 설명을 보내지 않습니다.
- Object URL은 화면 교체, 사진 삭제, 초안 삭제, 컴포넌트 해제 시 폐기합니다.
- 사진 설명을 포함한 모든 사용자 문자열은 HTML로 삽입하지 않고 텍스트로 렌더링합니다.
- 원본 PDF와 추출 텍스트를 저장하지 않는 기존 경계는 그대로 유지합니다.

## Online Portfolio Boundary

향후 온라인 포트폴리오에서는 경력별 `portfolioPhotos` 전체를 보여줄 수 있습니다.
이 기능을 시작하려면 계정, 서버 API, 객체 저장소, 명시적 게시 동의, 재게시, 철회, 삭제, 접근 제어를 별도 명세로 승인해야 합니다.
로컬 사진을 추가한 행위는 온라인 게시 동의로 간주하지 않습니다.
현재 구현은 공개 URL을 만들거나 브라우저의 사진을 서버로 전송하지 않습니다.

## Accessibility and Interaction

- 사진 조작은 키보드로 접근할 수 있는 실제 버튼과 라디오 입력을 사용합니다.
- 이미지 미리보기의 대체 텍스트는 사진 설명을 사용합니다.
- 설명을 아직 입력하지 않은 편집 상태에서는 `설명을 입력하지 않은 작업 사진`을 임시 대체 텍스트로 사용합니다.
- 오류는 색상만으로 전달하지 않고 해당 필드와 단계 상단 요약에 텍스트로 표시합니다.
- 대표사진 선택 상태는 시각적 표시와 `checked` 상태를 함께 제공합니다.

## Acceptance Criteria

- 기존 버전 1과 버전 2 초안이 사진 없이 정상적으로 복원됩니다.
- 상세 위치와 주요 이력은 구조화된 초안에 저장되고 복원됩니다.
- 프로필 사진은 최대 1개이고, 경력별 작업 사진은 최대 6개입니다.
- 작업 사진 설명을 비워 둔 상태에서는 STEP 04로 이동할 수 없으며, 어느 경력의 어떤 사진을 수정해야 하는지 안내합니다.
- 한 경력에서 대표사진은 최대 1개이고, 다른 사진을 선택하면 기존 선택이 해제됩니다.
- 대표사진을 삭제하면 대표사진 선택도 해제됩니다.
- 일반 미리보기와 일반 PDF는 프로필 사진을 표시하고, 리뷰용 사본은 프로필 사진을 표시하지 않습니다.
- 일반 PDF와 리뷰용 PDF는 경력별로 선택된 대표사진만 표시합니다.
- 새로 고침 뒤에도 구조화된 초안과 로컬 사진이 복원됩니다.
- 초안 삭제 뒤에는 구조화된 초안과 모든 로컬 사진이 남지 않습니다.
- 끊어진 사진 참조와 고아 Blob을 복구 절차가 정리합니다.
- 의도적인 시험 네트워크 요청을 감지하는 검증기가 실패한 뒤, 실제 사진 추가·복원·출력 흐름에서는 외부 전송 0건을 확인합니다.
- 개인 메뉴 사진, 공개 포트폴리오, 계정 동기화, 서버 업로드는 구현되지 않습니다.

## Deferred Scope

- 개인적으로 만들거나 개발한 메뉴를 이력서 전체에 연결하는 사진 영역.
- 사진 순서 변경, 경력 사이의 사진 이동, 자르기 편집기, 필터, 주석 도구.
- 레스토랑 자동 검색, 위치 자동 완성, 레스토랑 엔터티 병합.
- 미쉐린 가이드나 The World's 50 Best Restaurants 자료의 자동 조회와 검증.
- 공개 온라인 포트폴리오, 공유 링크, 계정 동기화, 서버 백업.
